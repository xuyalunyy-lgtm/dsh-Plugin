## 已知非阻塞限制

- 同一仓库的外部 Git 进程不受插件互斥锁控制，多次读取不是原子快照；实际写入仍重新验证。
- v0.6.0 中，旧总览批次失效但请求尚未结束时刷新点击可能暂时不执行；v0.6.1 改为一直展示读取中并禁用刷新，待原请求结束后解锁。两个 worker 的并发上限仍是单面板维度，服务端另有全局请求预算。
- v0.6.1 复用同一范围及 generation 下尚未完成的分支标记请求，重复点击不再叠加；真正刷新仍使旧响应失效。symbolic 分支别名标记未专门展示，但真实删除会被服务端拒绝。
- 操作记录只存当前宿主进程内存；重启会清空。极端日志 finish 异常会保留 running 槽位，需要重启恢复，不能据此推断实际 Git 操作未发生。
- v0.6.1 当前仓库记录筛选已改为后端按仓库过滤再取最近 100 条；仍受宿主全局保留容量限制，不代表该仓库所有历史。
- 客户端测试使用轻量 React hook 模拟，不替代真实 GUI 的视觉、键盘与窄面板验收。必须重启 DSH 并刷新现有 GUI 后人工检查。

## v0.8.0 全分支拓扑范围修复（2026-11-06）

用户截图证实 v0.7.0 只显示当前分支一条提交，不符合其要求。只读核对截图仓库 HEAD 可达 1 条、全部引用可达 50 条，其他历史位于本地 `publish/main` 和远程跟踪 `origin/main`。这不是样式问题，而是默认历史查询范围过窄。

本版客户端默认 overview 携带 historyLimit=100，服务端从本地分支/远程跟踪分支/标签及已读取 HEAD 查拓扑，取 limit+1 以确定 hasMore，再截到窗口；保留无参旧 API 的 HEAD100 契约。limit 在请求入口校验为 100..1000 整数，其它路由不接受该参数。HEAD 未出生但存在其他引用仍可读；额外标明浅克隆。
