# 会话管理 / Session Manager

当前 DSH Web GUI 的会话管理插件，入口为左侧导航中的 **会话管理**。

## 功能

- 按工作区筛选会话；搜索标题、会话 ID 和目录；分页查看。
- 工作区眼睛按钮：点击隐藏/显示，状态持久保存；支持临时勾选“显示已隐藏的会话”。
- 在指定工作区新建会话。
- 把历史迁移到另一个已注册工作区，在目标工作区继续聊天。
- 可恢复删除（原生归档）；在“已删除 / 归档”中恢复。
- 多选本页会话、全选本页及选择本页空会话，确认后批量归档并逐项展示结果。
- UI 和智能体工具 `session_manager` 使用同一组 Host 操作；修改前检查版本，重复请求使用相同凭证。

## 多选删除空会话（v1.3.0）

1. 在活动会话列表勾选左侧复选框；或点击 **全选本页** / **选择本页空会话**。
2. 点击 **删除所选**，核对确认框中的会话数量、标题和 ID 后确认。
3. 操作逐项执行：成功项归档，运行中、状态冲突或不可读取项保留并报告原因。需要再次处理失败项时，刷新后重新勾选。

- 只选择当前页的可操作会话，不会暗中处理其他分页、隐藏筛选或搜索范围之外的会话。切换筛选、翻页、刷新会清空选择。
- “空会话”以实际记录判断，不依赖“新会话”标题；包含消息、工具调用、目标、团队、子智能体或未知内容的记录不会被当作空会话。初始配置、标题等不算对话内容。即使自动选择为空，仍须人工确认。
- 批量删除仍为可恢复归档，不会清理磁盘或永久擦除。后台会逐项重新校验状态，不自动强制停止任务。
- 结果未确认时只使用 **重试原请求**，不要重新另建批量请求；重试不会再次归档已成功后又恢复的会话。

## 工作区隐藏 / 显示

页面顶部 **工作区可见性** 区域列出全部已注册工作区。点击工作区右侧的眼睛按钮切换：睁眼为显示，划线眼睛为隐藏。隐藏后，默认会话列表、搜索及工作区筛选不再显示其会话；该区域仍保留这个工作区，方便再次点击恢复。

- 勾选 **显示已隐藏的会话** 可临时查看所有隐藏工作区的会话，不修改其保存状态。
- 新建和迁移目标默认不列已隐藏工作区；需要时先点击眼睛恢复显示。
- 隐藏设置仅作用于此插件页面，不影响 DSH 原生侧栏、文件、会话归档、访问权限或任何任务运行。
- 设置由 Host 持久化，在本机同一配置的不同会话/浏览器共享；其他已打开页面刷新后读取最新状态。版本冲突会拒绝覆盖，请刷新核对后再次点击。
- 可见性请求绝对赋值并带唯一凭证；重试旧请求不会把新设置再翻转。待确认操作沿用页面的“重试原请求”入口。

## 移动的含义与边界

当前 DSH 没有修改原生会话所属工作区的公开接口，原始工作区信息不可变。因此本插件采用经用户确认的安全迁移方案：

1. 校验源会话、目标工作区、活动状态与读取版本。
2. 临时归档源会话，阻止新的模型步骤进入，然后复查历史快照。
3. 在目标工作区建立 **新 ID** 的会话，承接历史并把有效执行目录设为目标目录。
4. 新会话持久化并关联目标工作区后，源会话保持归档，作为恢复依据。
5. 发生失败时尽量恢复源会话；结果不确定时保留原请求凭证，只能用同一请求重试。

迁移不是复制项目文件：旧消息、工具结果、绝对路径、附件引用仍保留原意。继续操作前应核对原目录引用。不能原地保留会话 ID。

### 含目标、提醒、团队或子智能体记录的会话

v1.2.0 不再因为历史中出现这些记录就拒绝迁移。源事件、序号、消息、工具结果及附件引用完整保留，按 DSH 原生 fork 的继承切点建立独立会话：

- **目标**：目标状态和历史保留；新会话的自动继续默认未启用，需要用户明确恢复。
- **提醒**：历史记录保留；Host 提醒仍绑定原会话，不会复制成新的提醒。仍有效的提醒属于实际活动，需要先处理后才能归档/迁移。
- **团队、子智能体**：旧成员、任务和目录事实作为历史保留，不转交给新会话；新会话不会获得操控旧成员的权限。需重新组织的工作应在新会话明确创建。
- **工作流**：执行记录保留，但不会因为读取历史而重新运行。
- **仍会阻止迁移**：原会话/实际后代运行中、正在创建子智能体、后台任务、排队输入或未闭合轮次/工具调用，以及源本身是子智能体会话。

若仍提示“正在运行”或“排队输入”，先回原会话完成/停止对应活动，刷新列表后重试。插件不会为解除保护自动停止任务，也不会删除关联历史。

## 删除与恢复

“删除”是 DSH 原生归档，不是永久擦除：不会清理磁盘日志，不提供隐私擦除保证，也没有自动到期清理。归档会移除置顶；恢复回到原工作区，不恢复原来的置顶和已停止工作。运行中或存在后台活动的会话应先结束任务，再操作。

## 使用

1. 打开左侧 **会话管理**；若安装后尚未出现，请刷新当前 DSH 页面。
2. **新建会话**：选择工作区，确认后点击“打开新会话”。
3. **移动**：点击对应会话的“移动”，选择目标工作区，确认迁移。
4. **删除**：确认归档；在 **已删除 / 归档** 标签页点击“恢复”。
5. 若提示请求结果未确认，使用 **重试原请求**。不要关闭当前标签页或另造请求来重复迁移。

未确认操作凭证保存在当前标签页的 sessionStorage 中；关闭标签页、换浏览器或设备不会携带该凭证。新建与迁移不会自行发起模型请求。Host 端成功/恢复凭证永久保留，最多 4096 条，满后拒绝新的修改请求，不会通过自动清理牺牲防重复保证。

插件内的修改串行执行并校验读取版本；DSH 原生操作没有跨插件原子锁。迁移期间请勿在其他标签页打开目标副本或对源会话做恢复、重命名等修改。并发变化会尽量检测并取消迁移，但不能将其当成跨进程事务。

## 启动故障修复（2026-11-04）

本地 1.4.0 草稿曾包装 `sidebar.workspaces` 并重复声明原生工作区浏览器已拥有的子插槽，触发 DSH 客户端注册失败及 `web boot: 1 entry did not activate`。当前已移除这段原生侧栏接管，保留会话管理页、持久化隐藏设置和其他会话操作；隐藏不再影响原生侧栏。修复不删除会话、归档或插件持久化数据。

若此前已将插件停用，应在插件管理器中重新启用本插件，然后正常重启 / 刷新原有 GUI。已安装为目录链接时会读取链接目标的修复代码，但不能据此认定当前已打开的页面已重新加载成功。

## 开发与安装

插件使用普通 JavaScript，无需构建，不执行安装脚本。运行时依赖清单中声明的 Zod；本地目录开发先在本插件目录安装依赖，再通过插件管理器安装，避免链接目录缺少依赖。页面没有 CDN、远程图片或字体。

```powershell
node --check index.js
node --check controller.js
node --check client.js
node --test
```

通过 DSH `plugin_manager` 安装本目录。不要手写配置目录或移动底层会话文件。首次安装后以工具结果 `application` 判断是否已应用；替换已安装的 Host 模块可能需要重启 DSH。
