# 青岚主题 · 自定义背景

为 DeepSeek Harness 提供参考图风格的柔和绿色配色，以及可替换的本地背景装饰层。不替换应用根节点、聊天组件或输入框，不修改 Harness 安装目录。

## 使用

安装启用后打开 **设置 → 青岚主题**。

- 12 套配色按浅色 / 深色分组，每套展示色卡，当前主题显示选中标记。
- 浅色 7 套：青岚（浅绿）、暖杏（米色）、晴空（浅蓝）、雾紫（薰衣草）、樱雪（浅粉）、薄荷（青碧）、云银（冷灰）。
- 深色 5 套：夜森（深绿）、星海（深蓝）、暮紫（暗紫）、摩卡（深棕）、曜石（炭灰）。
- 上传：PNG、JPEG、WebP，每张最多 3 MB；选择新图片会替换旧图片。
- 背景显现度：0–25%，默认 12%，限制上限以保护前景文字可读性。
- 模糊：0–16px；铺放方式：裁切铺满、完整显示、平铺。
- 植物光斑：可独立开关，与图片叠加。
- 关闭「启用自定义外观」恢复原有主题，保留本地背景偏好。
- 「主题配色 / 背景图片」分区切换，顶部显示当前配色与版本。
- 背景默认显示实际效果缩略预览，包含示例文字；可以切换查看未加工原图。
- 「重置背景参数」恢复显现度、模糊、铺放和纹理，保留图片、配色及启用状态。
- 「恢复全部默认设置」先展开确认区，确认后恢复浅绿、默认纹理并移除保存的背景图；取消不修改设置。

背景采用 shell.overlay 的点击穿透淡化装饰层，覆盖整个应用视口；它不是插入到宿主组件背后的 CSS 背景，因此高显现度下也会轻微影响前景色。设置页「实际效果」与全局共用同一背景层组件，显现度、模糊、铺放和纹理参数一致；缩略预览尺寸不同，裁切范围不等于全窗口截图。「查看原图」显示未经淡化和模糊的图片。不会把参考截图当作背景图。

## 存储与隐私

从 1.3.0 起，图片与设置通过已认证的 Harness Connection 接口保存到当前 Host 的 `local-qinglan-theme` 存储域，不再以页面端口下的 localStorage 作为权威来源。默认持久性由 Host 配置的 storageDomain 后端提供，切换浏览器、清理页面数据或改变端口不会删除 Host 已保存的数据。同一 Host 上的已授权页面共享外观，不是每个浏览器的私有设置。图片不发送到第三方，但会传到你连接的 Harness Host；远程部署请使用 HTTPS。

图片以内容哈希分开存储，偏好只引用图片 ID。修改普通参数不会重新上传图片。每次写入都校验 revision，并发冲突会拒绝写入并重新读取，避免无提示覆盖。页面聚焦/重新可见或点击「重新读取 Host 设置」时刷新，不承诺即时跨页面推送。保存失败时显示错误；等待「已保存到 Host」再关闭页面。突然退出或网络中断可能丢失未确认的修改。

旧版迁移：若当前页面 origin 能读取旧键 `dsh.qinglan.presentation.v1`，且 Host 尚未初始化，显示「迁移此浏览器的旧设置」。迁移需点击确认，不删除旧副本、不覆盖已有 Host 设置。浏览器不能读取其他端口的 localStorage；旧数据只能在原来源页面可访问时迁移，不能声称自动找回所有历史端口数据。

禁用插件会释放配色覆盖和 slot 注册，恢复宿主外观；Host 数据仍保留。所有请求使用 Harness 的认证及 Host/Origin 检查，不另建公开文件服务器。工具 `qinglan_theme` 与 UI 调用同一仓库操作，read 返回 revision，update/reset 使用 expectedRevision。

## 1.4.0 命名外观方案

- 「外观方案」分区可保存、应用、重命名、删除方案，最多 20 套，名称去首尾空格后 1–40 字符且不可重名（忽略大小写）。
- 保存的是 Host 已确认的当前配色、图片引用和背景参数；保存前会先提交待保存调整。
- 图片共享内容地址，不为每个方案复制图片。修改当前背景或重置当前外观，不会破坏已保存方案的图片。
- 删除方案需要 UI 二次确认，不修改当前外观；仅在图片没有被当前外观和任何方案引用后清理。
- 重置当前外观保留已保存方案。全部方案操作也暴露在 `qinglan_theme` 工具，仍需 expectedRevision。
- 兼容旧存储文档：缺少 presets 字段按空列表读取，成功修改后持久化该字段，不改变存储版本号。

## 1.3.0 Host 持久存储

- 使用已发现的 `storageDomain` 和已认证 Connection Fetch 接口，图片和参数分离。
- 显式迁移当前 origin 的旧偏好，不覆盖已有 Host 数据。
- Host 串行提交、版本冲突检测，Client 合并拖动并按序提交；并发刷新合并为同一个读取请求。
- Agent 工具与 UI 共用同一仓库，响应不包含背景图片内容。
- 图像校验包含规范 Base64、3 MiB 上限及 MIME 魔数，不替代完整图像解码；浏览器上传还会解码检查。
- 存储单次提交失败保留旧文档，未引用的图片在后续成功提交后尽力清理。

## 1.2.0 设置体验优化（历史实现）

- 主题与背景分区展示，顶部显示当前配色及版本；主题卡片预留选中标记位置。
- 默认效果预览与全局背景共用渲染逻辑，附示例文字，并支持切换原图。
- 滑块即时预览，停下 250ms 后合并保存；松手、失焦、键盘松开、切换分区、关闭设置、页面隐藏或退出时尝试保存。极端进程崩溃仍可能丢失尚未写入的预览值。
- 保存失败会提示并回退到上次成功状态。跨页面收到有效存储更新时丢弃本页旧的待保存值，避免过时定时器回写。
- 延续原存储键和单对象格式以避免迁移图片；本轮通过减少写入次数优化，不拆分图片存储。每次最终保存仍包含图片数据。
- 背景参数重置不删除图片；全部恢复需要明确二次确认，并在完成后恢复按钮焦点。
- 回归命令：`node test/contrast.test.mjs`（28 项）以及 `node test/settings.test.mjs`（10 项）。后者验证纯保存队列、重置参数与背景显示规则；UI 接线使用静态断言，不等于浏览器交互实测。

## 1.0.1 原生界面颜色兼容修复

- 原生外观卡片使用独立的 `bg-module-platform` 作为选中背景，现在与主题文字成对覆盖。
- 补齐悬停、设置卡片、菜单背景与菜单图标的已确认语义 token。
- 针对原生设置导航的 `data-shortcut-modal="settings"` / `aria-current="true"` 做局部配色兼容，选中项统一背景与文字，并增加左侧强调线。不使用宿主生成的类名，不全局强制文字颜色。
- 切换主题时原子替换颜色层，避免先释放旧层引起短暂混色。
- 三套配色的普通、选中、悬停及菜单背景与主要文字进行 WCAG 对比度回归检查（至少 4.5:1）。检查不包括背景装饰层叠加，也不等于所有宿主组件的视觉验收。
- 关闭自定义外观会同时移除兼容样式；本地图片与偏好键不变。

## 实现与验证

- Host 使用锁定的 Zod 4.1.12 校验存储记录；无安装脚本，无编译步骤。开发测试先运行 `npm ci --ignore-scripts`，然后 `node --test test/*.test.mjs`。
- React 使用 Harness 模块加载器提供的实例。
- 使用已发现的 `theme.overrideTokens`、`settings.section`、`shell.overlay` 与 locale 服务。
- 自定义 token 层提供 light/dark 两组值，使所选固定配色在宿主深浅模式中一致。
- 控件使用宿主主题 token，支持键盘焦点、标签、状态提示与中英文。
- SVG 图标为本插件原创。

可检查语法：`node --check client.js` 与 `node --check index.js`。

当前环境未提供浏览器控制；语法、包结构、安装结果与实时 slot 注册可检查，但实际截图、文件选择、刷新持久性和关闭后的视觉恢复仍需在 UI 人工验收。
