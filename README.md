# codex Break defense

减少模型**无依据的防御性编程**：不为想象中的问题新增兜底、重复校验、静默吞错、兼容层、过早抽象或重试。目标是最小且完整的实现，不是代码越短越好。

## 使用

点击左侧栏 **插件 → 已安装插件 → codex Break defense** 进入组合包详情，分别控制两个组件条目的右侧开关（不是“设置 → 内置插件”）：

- **codex Break defense**：原有的精简编码指导。
- **减少多余安全提醒**（v1.1.0 新增）：已明确授权的正常开发任务不反复索要同一确认，也不重复泛泛安全警告；只在影响判断时简短指出具体风险。授权范围不清、新的破坏性影响、敏感数据暴露或超范围外部操作仍应确认，工具必需的审批照常执行。此项按本次用户选择启用，可单独停用，不影响精简编码。

两个开关不修改沙箱和审批策略。不新增设置页面、工具或依赖。仅切换插件通常无需重启；更新已安装的运行模块时，以插件管理器返回的状态为准，若提示 `restart-required` 则需要重启 DSH。

启用后，标准提示组装会在后续模型步骤中加入一段固定英文编码指导。无需编辑项目文件或重启模型。已经发出的请求不会改变；已有历史中的指导不会被抹除，停用后若要完全排除历史影响，请新建会话。

## v1.4.0 拒绝冗余设计与重复验证

精简编码提示直接重写收紧，不继续堆叠口号，不新增开关或运行机制：

- 默认只做最小完整改动。“稳妥起见”本身不是新增校验、兜底、重试、恢复层或抽象的理由。
- 在真实输入边界校验，内部已由契约保证的结果不层层重复验证。
- 复用已有明确结论。只有相关内容改变、证据不确定、出现具体失败或项目强制要求独立检查时才重复验证；需求和必要检查通过后停止。
- 只运行项目要求及与本次改动直接相关的必要已有检查，不将小改动扩展为全面审计。
- 未经用户明确要求，不创建或扩展测试脚本、测试文件、测试用例及自制验证工具，包括临时脚本和内联验证脚本。
- 未经用户明确要求，不自行复制备份、创建快照或增加恢复层；项目规则强制要求的除外。不关闭项目或插件管理器已有的备份机制，也不自动删除已有备份。
- 保留必要鉴权、安全检查、事务、数据完整性和资源清理，不删除未经核实的已有保护。

## v1.3.0 减少误拒绝与授权安全测试

合并进现有 **减少多余安全提醒** 开关，不新增开关：

- 按实际目的、目标、操作及影响判断任务，不仅因“破解、利用、攻击、PoC”等关键词或双重用途直接拒绝。
- 支持允许且明确授权范围内的 CTF、自有靶场研究、漏洞复现，以及用户明确要求的利用/PoC 脚本。单说“用于测试”不构成任意目标的无限授权。
- 不虚构平台规则，不把建议当禁令或把尚未验证当作不可能；部分内容受限时继续完成可独立提供的允许部分，并给出可行替代。
- 只在信息缺口实质影响判断时提出关键问题；已有明确授权不重复询问，真实审批与安全边界照常遵守。
- 不擅自新增测试脚本或验证工具；安全研究支持不等于自动创建普通测试文件的许可。

以上是减少误判的提示级指导，不解除模型服务端限制，也不修改沙箱、审批或工具权限。

### 临时纠偏：发现模型写复杂后再发送

以下指令只作为可复制示例，不自动注入。避免把“已经过度设计、必须返工”当成每个任务的前提：

```text
这次实现超出了需求，请收缩，不要继续追加补丁式防御。

重新对照原始需求，检查本次新增的分支、校验、兜底、配置和抽象：移除仅由假想场景支撑的部分，将不必要的间接层改回直接实现。

优先解决产生问题的原因，不要通过更多 catch、默认值和重试把问题隐藏起来。只整理本次改动，不清扫无关旧代码，也不要为了精简删除未经核实的已有保护。

给出缩减后的实现，运行相关测试，并用几句话说明删掉了哪些不必要的东西；不需要另建审计报告或诊断体系。
```

## 指导内容

- 当前需求直接实现，防御措施必须对应具体需求、真实契约或合理可预见的失败模式。
- 对已由内部契约保证的值，不重复添加类型和空值检查；外部数据不能仅凭静态类型视为可信。
- 不用 `catch` 后返回空对象或默认值伪造成功，按契约处理预期错误，其余错误清晰传播。
- 保留不可信输入边界校验、鉴权、安全、事务、数据完整性和必要资源清理。
- 不因“没找到依据”就删除已有 guard；先核对调用链、契约和测试。
- 只修改当前任务相关代码；审阅本次 diff 后，运行项目强制检查及最少必要的相关已有测试。复用已确定的结论，不无故反复验证；缺少覆盖就说明限制。
- 未经用户明确要求，不新增或扩展测试脚本、文件、用例及自制验证工具（包括内联脚本），不自行备份文件、创建快照或恢复层；项目强制要求除外。

## 作用范围和限制

- **不是越狱或安全绕过插件**，不修改权限、审批、工具定义、模型路由或适配器，不自动删除或重写代码。
- 名称按用户要求保留为 **codex Break defense**，但它是当前配置的全局编码指导，**并非只影响 Codex**。
- 使用标准提示组装的当前及后续会话/内部子智能体可获得指导；独立外部 Codex CLI 子进程、其他配置、覆盖完整系统提示的自定义 preset 不保证接收。
- 这是提示级行为引导，不修改模型权重，也不能保证每次生成都遵守。最终仍需审查具体 diff。

## 机制

Host-only Cordis bundle，通过官方 `ctx.systemPrompt.section()` 注册唯一段落 `local:codex-break-defense`，排序值 `10300`，不覆盖其他提示段、不使用 `complete`，文本不做模板插值。注册由插件 effect 管理，停用/卸载会撤销该注册。

精简编码入口是 `index.js`；可选提醒入口是 `reminders.js`，只通过 `ctx.systemPrompt.section()` 注册 `local:codex-break-defense:reminders` 段落，排序值 `10310`。两者各自由插件 effect 撤销，不依赖或调用权限服务，也不拦截工具结果。

显示名、描述和原创 SVG 图标通过各自的标准资源导出；代码及图标采用 MIT 许可。无网络请求、安装脚本、后台循环或模型额外调用。v1.2.0 的精简编码指导为 228 个英文词（原 187），提醒/执行指导为 157 个英文词（原 106），两项合计增加 92 个英文词。关闭对应开关就不注册该段；词数仅用于比较文本长度，不代表模型实际 Token 数。

## 验证

使用 Node.js 运行：

```powershell
node --check index.js
node --check reminders.js
node --test test/*.test.mjs
```

自动化测试验证注册、撤销与重新启用、提示边界及本地资源。它们不等于模型行为评测。可用以下相同任务在启用前后人工比较：

| 场景 | 期望 |
| --- | --- |
| 已由调用契约保证的内部纯函数 | 不新增重复空值检查、默认成功返回值或通用框架 |
| HTTP/JSON 外部输入 | 保留运行时校验和鉴权，不因 TypeScript 类型删除检查 |
| 文件/数据库失败 | 不吞错伪成功，保留事务回滚和必要清理 |
| 幂等网络操作与支付请求 | 只在有依据时有限重试，未知支付结果不盲重试 |
| 小范围修复 | 不清扫无关代码，完成项目必需测试 |

实际改进幅度取决于模型和任务；本插件不做自动 A/B 模型请求，以免消耗额外配额。
