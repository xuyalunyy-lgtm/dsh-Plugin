# DSH Git 工作台 · 0.5.0

适配本机 DSH 0.2.1-rc.2 插件接口。一个用于日常 Git 工作的多仓库面板：**选仓库 → 查看改动 → 暂存 → 提交 → 同步**。不创建独立服务，使用现有 GUI 的认证接口。

## 下一版：多仓库状态总览

「仓库总览」标签按需读取已发现仓库的分支、改动数、冲突数和同步数量，支持按改动、待推送、待拉取、冲突或错误筛选。每次最多两个并发只读请求，不加载各仓库完整历史，不自动 Fetch。每条结果附读取时间；同步数量以本地远程跟踪引用为准，未知时显示 `?`，不伪装成已同步。切换会话或重新检索会取消旧批次后续排队读取；写操作会使对应仓库总览失效，需刷新后再查看。

## 0.5.0 分支管理

进入 **分支管理** 标签：

- **创建**：在「新建本地分支」输入名称，点击「创建分支」并确认；基于当前确认的 HEAD 创建，不自动切换。没有首次提交时会提示先提交。
- **切换**：点击分支行的「切换」，要求工作区干净。
- **删除**：点击分支行的「删除」，弹窗显示仓库与分支，并要求输入完整分支名；名称匹配后才能确认。
- **保护**：只删除确实存在的本地分支。当前分支、其他 worktree 正在使用的分支、尚未合并到当前 HEAD 的分支一律拒绝；未创建 HEAD 的空仓库也不能删除。
- **非强制**：额外校验相对 HEAD 已合并后，仍使用 Git 原生 `branch --delete`（即 `-d`）。Git 对目标分支 upstream 的额外检查也保留，因此即使已合并到 HEAD，原生 Git 仍可能拒绝删除。
- **范围**：不使用 `-D`，不删除远程分支，不删除工作区文件。成功后自动刷新列表；失败保留分支并要求刷新再尝试。

删除遵循 Git 原生语义，会移除该本地分支引用、其 reflog 及相关分支配置。不要和终端/其他工具同时修改同一仓库：插件重读 HEAD 和目标分支来减少竞态，但不保证跨外部进程的原子性。

## 0.4.0 体验优化

- **一次请求完成刷新**：概览合并状态与同步元数据，避免重复执行 status / HEAD / 分支读取；不使用跨刷新缓存，写操作前仍重新校验状态。测试中的已提交、无 upstream 仓库，读取命令从 13 条降为 9 条（减少 4 条；不等同于固定比例的实际耗时提升）。
- **刷新不闪空白**：保留上次列表并标明正在刷新。刷新失败或写操作报错后，旧数据仍可查看，但必须刷新成功才能继续写操作。
- **提交草稿按仓库保留**：切换仓库和重新检索不会清空；提交成功才清除对应仓库的草稿，失败保留。
- **未跟踪文件可以预览**：仅预览未忽略的 UTF-8 普通文本文件，最多 256 KiB / 2000 行；二进制、无效 UTF-8 或链接会明确提示，不为了预览而暂存。
- **差异分页与行号**：每页最多渲染 200 行，显示新旧行号、增删行数，支持上一页/下一页和自动换行；文件头不计入增删行数。超大差异最多解析/展示前 20000 行并明确提示，避免过多对象占用浏览器内存。
- **筛选即操作范围**：输入筛选条件后，分组暂存仅操作筛选出的文件，确认中列出准确路径。单次最多 200 个路径，超出请缩小筛选范围。
- **错误提示可操作**：区分认证失败、未配置 upstream、仓库状态变化、脏工作区、分叉以及所有者检查，并保留可展开的原始错误。

草稿保存在当前浏览器标签页的 sessionStorage，按会话、扫描根目录和仓库隔离，不上传服务端。浏览器限制存储时退化为组件内存。相同来源的页面刷新可恢复；关闭标签、清理存储或 DSH 重启更换端口后不保证恢复，不能作为持久备份。

## 直观布局

- 顶部仓库选择器：可折叠列表、名称/路径筛选，始终显示扫描根目录和当前仓库完整路径。
- 分支与同步栏：显示当前分支及相对 upstream 的领先/落后数量，提供 Fetch / Pull / Push。
- 改动页：按「未暂存」「未跟踪」「已暂存」「冲突」分组，避免原始 XY 状态难以理解。
- 差异详情：点击文件或提交打开差异，宽面板左右布局，窄面板上下布局；不会离开文件列表。
- 提交区：输入说明，只提交已暂存内容；未暂存文件不会被自动加入。
- 提交历史页：最近 100 条，作者、日期、哈希、引用及合并标记（不是完整拓扑图）。
- 分支管理页：本地分支创建、切换、安全删除，以及远程/upstream 信息。
- 每项写操作先显示确认层，明确仓库、当前分支、操作目标；完成显示结果和可展开 Git 输出。

## 常用操作

| 功能 | 行为与约束 |
| --- | --- |
| 单文件 / 分组暂存 | 分组按钮仅作用于当前筛选结果，不影响隐藏文件；单次最多 200 个路径 |
| 取消暂存 | 保留工作区内容；支持第一次提交前的空仓库 |
| 提交 | 只提交暂存区，要求非空说明且没有未解决冲突；不 amend、不自动 add |
| 创建分支 | 基于当前 HEAD 创建，不自动切换 |
| 切换本地分支 | 工作区必须干净，包含未跟踪文件；不强制、不猜测远程分支 |
| 删除本地分支 | 输入分支名确认；拒当前/其他工作树占用/未合并到 HEAD 的分支；保留 Git 原生 `-d` 检查 |
| Fetch | 从当前分支配置的 upstream 远程获取该分支的跟踪引用，不改工作区 |
| Pull | 仅快进，不 rebase、不自动合并、不自动 stash；要求工作区干净 |
| Push | 当前分支明确推送到其已配置 upstream；不强推、不 mirror、不附带 tag |

**GUI 提交会禁用本地 hooks 和 GPG 签名，网络操作也不执行本地 hooks。** 这样避免宿主后台弹窗与任意 hook 程序；如果项目依赖 hook 校验或要求签名提交，请改用终端，不要通过本面板提交。

所有网络操作均为非交互：可复用已有凭据助手/SSH agent，但不会让你在面板输入密码或接受未知 SSH 主机。认证失败时请在可信终端完成登录，再回面板刷新。未设置 upstream 时，网络按钮不可用；首次推送和设置 upstream 请用终端。本面板不会猜测远程目标。

不存在强推、硬重置、丢弃改动、强制删除分支、删除远程分支、删除/克隆仓库等高风险入口。冲突在编辑器中解决后，逐文件暂存以标记解决；本面板不提供冲突编辑器。

## 多仓库检索

自动检索**会话工作区根目录（第 0 级）及下方最多 5 级**。根目录本身不必是 Git 仓库；识别普通仓库、嵌套仓库、worktree 和子模块，找到一个仓库后继续扫描其内部。第 6 级不扫描。

- 不跟随符号链接或 Windows junction，不进入 `.git` 元数据目录。
- 单次最多 5000 个目录、100 个仓库、5 秒扫描预算；不完整时明确提示，可缩小会话根目录重试。
- Git `safe.directory` / 所有者检查失败会显示扫描提示，不自动更改信任设置。
- 会话根目录在仓库子目录中时，`.` 是兼容的「上级仓库」选项，作用于完整仓库。
- 其他仓库选择只能指向当前会话根目录下最多 5 级的真实仓库。
- 仅在聊天中提到一个目录不会改变扫描根目录，请使用工作区指向目标工程的会话。

## 安装 / 升级

1. 安装 Git。插件优先使用 PATH，也支持 Windows 常见 Git 安装目录。
2. 在 DSH「插件 → 添加插件」输入：
   ```text
   file:D:/xuyl/tool/DSH/dsh-git-visualizer
   ```
3. 启用 `dsh-git-visualizer`。从旧版升级时从此路径更新/重新安装，不要再引用父目录 `file:D:/xuyl/tool/DSH`。
4. 完全退出并重开当前 DSH，再刷新原 GUI。宿主代码不能仅靠浏览器刷新升级。
5. 打开目标工作区会话，在右侧面板添加「Git 工作台」。顶部版本应为 **v0.5.0**。

`file:` 是安装副本，不随源码自动更新；开发可使用 `link:D:/xuyl/tool/DSH/dsh-git-visualizer`，但宿主更改仍可能需要重启。此插件不依赖 HMR，不启动另一个服务。

## 安全与并发

插件以 DSH 宿主权限运行，不等同于会话工具沙箱，仅在可信仓库使用。Git 配置、凭据助手或过滤器可能包含外部程序；禁用 hooks 不代表整个仓库变成安全沙箱。

- 现有 `connection.fetch` 认证路由：复用 Host/Origin 检查、登录 cookie 和 owner 限制，无 CORS、无新服务、不读取或复制 token。
- 操作精确白名单；浏览器不能传入任意命令、Git 参数、cwd 或远程地址。
- 仓库先经过服务端发现/选择校验，文件路径禁越界、Git 元数据及链接祖先，使用 literal pathspec 和无 shell 的参数数组。
- 请求必须确认并携带查看时的 HEAD/branch；变化后拒绝并要求刷新。每仓库在插件内串行写入，最多四个全局请求。
- 不与终端/编辑器同时改同一仓库：插件锁不覆盖外部进程，也不保证 HEAD 未变化时暂存内容没有被外部工具修改。
- 本地调用超时 10 秒，网络调用最长 60 秒；超时后操作可能已有部分效果，请先刷新/检查状态，不要盲目重试。
- Git 输出上限 8 MiB；网络输出中的 URL 会脱敏，不自动重试失败操作。
- 所有测试写入仅发生在临时仓库和本地 bare 远程，不自动对用户工程提交/同步。

## 开发

此目录是独立 Git 仓库，后续修改仅在这里维护。

```powershell
# Node.js 20+，确保 Git 在 PATH
node --test --test-isolation=none test/*.test.mjs
```

- `index.js`：宿主路由、请求校验、仓库操作锁。
- `git-core.mjs`：只读状态、历史、差异及合并概览。
- `git-preview.mjs`：有界 UTF-8 预览，未跟踪校验及路径/链接/元数据防护。
- `git-actions.mjs`：白名单 Git 写操作与非交互网络操作。
- `repository-discovery.mjs`：五级扫描及安全仓库选择。
- `client.js`：已构建的 DSH ModuleLoader 客户端，React 由宿主提供，无需单独 npm build。
- `test/`：真实 Git 与 API 集成测试、轻量客户端交互测试。
