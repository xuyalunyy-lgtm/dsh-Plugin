# 专注日历：换设备恢复指南

适用插件：`dsh-focus-calendar` 1.3.0。

## 先分清两个文件

- **插件安装包 `.tgz`**：程序代码、中文/英文资源、图标与 Zod 运行依赖，不含你的待办数据。
- **数据备份 `.json`**：已保存的待办、完成状态、累计专注统计、时间设置、健康提醒工作时段规则和回收站。包含个人工作安排，请妥善保管。

本地 Git 仓库只保存源码；它不能替代数据备份，也不能在电脑损坏后自行恢复。请把安装包和最新 JSON 备份另存至可信网盘或移动硬盘。

## 在旧设备上备份

1. 打开「专注日历」，先保存正在编辑的任务。未提交草稿不在备份范围内。
2. 展开「备份与恢复」，使用导出按钮下载 JSON。
3. 将 JSON 与本版本插件安装包一起保存。备份是导出时刻的快照，后续修改需要重新导出。
4. 尽量在计时停止或暂停后导出，便于确认统计；运行中计时和系统通知授权不会在新设备自动恢复。

## 在新设备上安装

1. 安装并启动兼容版本的 DeepSeek Harness。本版在 DSH `0.2.1-rc.2` 接口上开发；跨版本请先检查兼容性。
2. 解压迁移资料包，把 `.tgz` 插件安装包放在固定、可读取的位置。
3. 在 Harness 的「插件 → 添加插件」中输入安装包的**绝对路径**，例如：

   ```text
   D:\Plugins\dsh-focus-calendar-1.3.0.tgz
   ```

   也可以在新设备的 Harness 对话中说：“请安装这个本地插件包”，并提供实际绝对路径，由插件管理工具安装。
4. 如果提示重启或刷新，按管理器提示操作。不要手改 Harness profile 的配置文件。
5. 打开侧栏「专注日历」，进入「备份与恢复」，选择 JSON 文件并查看预览。
6. 新设备为空时可选「替换」完整恢复任务和设置；如已有安排，先导出本机数据，再按需选择「合并」或「替换」。

## 合并与替换的区别

- **合并**：按任务 ID 去重，保留本机同 ID 项、本机时间设置及健康工作时段规则；只加入新 ID。预览会显示新增、重复和冲突数量。相同标题但不同 ID 不视为同一条任务。
- **替换**：导入备份中的任务、设置和回收站；执行前自动保存一份本机旧数据恢复副本。必须在预览后明确确认。
- **两种导入都会停止当前计时和提醒，并清除待显示/延后提醒及临时勿扰状态**，不会自动开启通知。
- 替换导入会恢复备份中的健康工作时段规则；旧版备份没有此字段时采用默认关闭规则。临时勿扰倒计时不属于备份内容。
- 防重复请求回执、编辑 token 和浏览器待确认请求不属于迁移内容。换设备前先处理待确认操作；不要把丢失凭证后的重新录入当作原请求的安全重试。
- 如果预览之后本机数据改变，导入会拒绝旧预览，请重新预览再确认。
- 输入文件最大 4 MiB；非法格式、重复 ID、无效日期或不支持的版本会被拒绝，不应写入部分数据。

## 导入后想撤回

替换前自动保留**最近一次**恢复副本，不是无限历史。使用恢复副本入口，重新预览并确认替换即可恢复；仍建议先导出当前数据。

删除待办后可立即「撤销」，或在回收站中恢复。回收站保留 30 天，过期后会自动清理；永久删除无法撤销。恢复的旧备份不会延长其中回收站条目的原保留期限。

## 需要重新设置的内容

- 系统通知权限需要在新设备手动授权。
- 专注、护眼和活动提醒需要手动重新启动。
- 未提交草稿只属于原浏览器标签页，不作为迁移数据。
- 数据不上传到外部服务。本插件不提供云同步，也不保证 DSH 关闭或电脑休眠时准时提醒。
- 提醒和临时勿扰使用绝对墙钟截止时间。若重启同时手动调整系统时间，实际等待时长可能改变；不承诺跨重启时钟调整仍严格计满真实 30／60 分钟。

## 安装方式说明

开发设备仍可使用源码目录的本地链接安装，不能随意删除或移动源码及 `node_modules`。迁移安装包不依赖原开发机器的绝对路径。安装包已声明捆绑 Zod 依赖；离线可用性仍取决于新设备 DSH 自身及其包管理环境是否完整。

升级已有版本时，如果管理器提示已安装，请通过管理器移除旧插件后安装新包。卸载代码不等于删除备份；升级前务必导出数据。不要将新版存储数据交给旧版本插件降级读取，以免旧 schema 忽略新字段。
