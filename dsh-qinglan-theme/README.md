# 青岚主题 · 自定义背景

为 DeepSeek Harness 提供参考图风格的柔和绿色配色，以及可替换的本地背景装饰层。不替换应用根节点、聊天组件或输入框，不修改 Harness 安装目录。

## 使用

安装启用后打开 **设置 → 青岚主题**。

- 12 套配色按浅色 / 深色分组，每套展示色卡，当前主题显示选中标记。
- 浅色 7 套：青岚（浅绿）、暖杏（米色）、晴空（浅蓝）、雾紫（薰衣草）、樱雪（浅粉）、薄荷（青碧）、云银（冷灰）。
- 深色 5 套：夜森（深绿）、星海（深蓝）、暮紫（暗紫）、摩卡（深棕）、曜石（炭灰）。
- 上传：PNG、JPEG、WebP，每张最多 3 MB；选择新图片会替换旧图片。
- 背景显现度：0–25%，默认 12%，限制上限以保护前景文字可读性。
- 模糊：0–16px；铺放方式：裁切铺满、完整显示、平铺。
- 默认柔和渐变：未选择图片时可开启或关闭；不再显示重复四点方块。有图片时只显示图片，不叠加装饰纹理。
- 关闭「启用自定义外观」恢复原有主题，保留本地背景偏好。
- 「主题配色 / 背景图片」分区切换，顶部显示当前配色与版本。
- 背景默认显示实际效果缩略预览，包含示例文字；可以切换查看未加工原图。
- 「重置背景参数」恢复显现度、模糊、铺放、位置和默认渐变开关，保留图片、配色及启用状态。
- 「恢复全部默认设置」先展开确认区，确认后恢复浅绿、默认渐变并移除当前背景图；取消不修改设置。

背景采用 shell.overlay 的点击穿透淡化装饰层，覆盖整个应用视口；它不是插入到宿主组件背后的 CSS 背景，因此高显现度下也会轻微影响前景色。设置页「实际效果」与全局共用同一背景层组件，显现度、模糊、铺放和默认渐变参数一致；缩略预览尺寸不同，裁切范围不等于全窗口截图。「查看原图」显示未经淡化和模糊的图片。不会把参考截图当作背景图。

## 存储与隐私

从 1.3.0 起，图片与设置通过已认证的 Harness Connection 接口保存到当前 Host 的 `local_qinglan_theme` 存储域，不再以页面端口下的 localStorage 作为权威来源。默认持久性由 Host 配置的 storageDomain 后端提供，切换浏览器、清理页面数据或改变端口不会删除 Host 已保存的数据。同一 Host 上的已授权页面共享外观，不是每个浏览器的私有设置。图片不发送到第三方，但会传到你连接的 Harness Host；远程部署请使用 HTTPS。

图片以内容哈希分开存储，偏好只引用图片 ID。修改普通参数不会重新上传图片。每次写入都校验 revision，并发冲突会拒绝写入并重新读取，避免无提示覆盖。页面聚焦/重新可见或点击「重新读取 Host 设置」时刷新，不承诺即时跨页面推送。保存失败时显示错误；等待「已保存到 Host」再关闭页面。突然退出或网络中断可能丢失未确认的修改。

旧版迁移：若当前页面 origin 能读取旧键 `dsh.qinglan.presentation.v1`，且 Host 尚未初始化，显示「迁移此浏览器的旧设置」。迁移需点击确认，不删除旧副本、不覆盖已有 Host 设置。浏览器不能读取其他端口的 localStorage；旧数据只能在原来源页面可访问时迁移，不能声称自动找回所有历史端口数据。

禁用插件会释放配色覆盖和 slot 注册，恢复宿主外观；Host 数据仍保留。所有请求使用 Harness 的认证及 Host/Origin 检查，不另建公开文件服务器。工具 `qinglan_theme` 与 UI 调用同一仓库操作，read 返回 revision，update/reset 使用 expectedRevision。

## 1.4.0 命名外观方案

- 「外观方案」分区可保存、应用、重命名、删除方案，最多 20 套，名称去首尾空格后 1–40 字符且不可重名（忽略大小写）。
- 保存的是 Host 已确认的当前配色、图片引用和背景参数；保存前会先提交待保存调整。
- 图片共享内容地址，不为每个方案复制图片。修改当前背景或重置当前外观，不会破坏已保存方案的图片。
- 删除方案需要 UI 二次确认，不修改当前外观；仅在图片没有被当前外观和任何方案引用后清理。
- 重置当前外观保留已保存方案。全部方案操作也暴露在 `qinglan_theme` 工具，仍需 expectedRevision。
- 兼容旧存储文档：缺少 presets 字段按空列表读取，成功修改后持久化该字段，不改变存储版本号。

## 1.3.0 Host 持久存储

- 使用已发现的 `storageDomain` 和已认证 Connection Fetch 接口，图片和参数分离。
- 显式迁移当前 origin 的旧偏好，不覆盖已有 Host 数据。
- Host 串行提交、版本冲突检测，Client 合并拖动并按序提交；并发刷新合并为同一个读取请求。
- Agent 工具与 UI 共用同一仓库，响应不包含背景图片内容。
- 图像校验包含规范 Base64、3 MiB 上限及 MIME 魔数，不替代完整图像解码；浏览器上传还会解码检查。
- 存储单次提交失败保留旧文档，未引用的图片在后续成功提交后尽力清理。

## 实现与验证

- Host 使用锁定的 Zod 4.1.12 校验存储记录；无安装脚本，无编译步骤。开发测试先运行 `npm ci --ignore-scripts`，然后 `node --test test/*.test.mjs`。
